Data: 2026-06-02

## Escopo implementado

- P1.5: `/m/config/groups` ganhou painel anti-ban para canais de destino com atualização de saúde, recomputar risco, snapshot manual, listagem curta de snapshots e recriação por novo JID.
- P1.6: `/m/config/preservacao` passou a exibir e controlar probe externo com status, iniciar/parar sessão e seleção de `probeAccountSessionId`.
- P1.7/P1.8: `/api/dashboard/status` agora retorna métricas de fila quando disponíveis; `/m` e `/m/checklistespelhamento` usam `hasSuccessfulLog` para validar o primeiro envio real e a home mostra saúde operacional da fila.
- P1.9: `/m/op/offer` consome o parâmetro `?url=` gerado pelo conversor mobile, carregando o link convertido diretamente no montador de oferta.
- P1.10: `/m/account/subscription` busca `publicPlans`, renderiza catálogo dinâmico de planos e usa o plano selecionado no checkout/PIX.
- P2.11: agendamento mobile recebeu aviso explícito de limitação do contrato atual (`scheduledCreate(text, scheduledAt)`) sem persistência de destinos explícitos. A persistência real continua bloqueada por mudança de API/schema.
- P2.12: `/m/config/preferences` passou a salvar também `platforms`, `feedGlobal` e `postToStatus` pelo contrato mobile seguro.
- P2.13: `/m/op/logs` agora envia busca de 3+ caracteres ao servidor via parâmetro `search`, mantendo filtro local para buscas curtas.
- P2.14: templates locais agora apontam para a rota mobile de variações globais persistidas.
- P2.15: home mobile ganhou atalhos visíveis para Broadcast e Automações além das tabs fixas.

## Riscos e decisões

- Sem migrations, sem alteração de `.env`, PM2, banco ou produção.
- A única mudança de API é aditiva: `/api/dashboard/status` inclui `queue` opcional usando `getBotMetrics(userId).catch(() => null)`.
- `scheduledCreate` continua sem destinos explícitos para evitar breaking change; a UI informa a limitação.

- `node --check` nos arquivos alterados.
- `npm run lint` no dashboard.
- `npm run build` no dashboard.

# Sessão: cooldowns de reconexão com prioridade de alta disponibilidade

## Mudanças
- Defaults globais de reconexão agora priorizam disponibilidade: flap exige mais closes para cooldown e segura por menos tempo; stable-close mantém proteção residual contra quedas periódicas e segura por 1 minuto por padrão.
- `connectionReplaced` permanece conservador para evitar ping-pong/double-possession.
- Adicionado helper puro para impedir stable-close cooldown quando o close contém `stuckMsgId` de retry-receipt travado.
- Heartbeat deixa de esconder reconexão presa após 2 minutos por padrão.

## Decisões
- Sem modo por cliente: todos os clientes devem ter alta disponibilidade.
- Cooldown não foi removido totalmente para preservar proteção em flapping real e `connectionReplaced`.
- `stuck_message_retry` segue com observabilidade, mas não deve aumentar downtime via stable-close cooldown.

- `node --test test/session-persistence-policy.test.js test/worker-crash-guard.test.js test/reconnect-policy.test.js` passou após cobrir o default de heartbeat de 2 minutos.

# Tasks: Painel de vendas da Shopee

**Input**: Design documents from `/specs/014-shopee-sales-dashboard/`

**Prerequisites**: `plan.md`, `spec.md`, `research.md`, `data-model.md`, `contracts/shopee-sales.openapi.yaml`, `quickstart.md`

**Tests**: Automated tests are included because the plan and quickstart explicitly require domain, route, UI guard, regression, lint, and build validation.

**Organization**: Tasks are grouped by user story so each increment can be implemented and validated independently. The integration remains read-only and introduces no migration, cron, PM2 process, shared cache, or changes to Shopee link generation and bot runtime.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel because it touches a different file and has no dependency on an incomplete task
- **[Story]**: User story from `spec.md`
- Every task names the exact file it changes or validates

### Safety Constraints Throughout

- Use only `req.user.sub` to select the Shopee credential.
- Keep all report data transient and scoped to one request/client component instance.
- Use GraphQL `query` only; never generate links or write Shopee/database state.
- Never expose credentials, raw payloads, buyer data, or unnecessary identifiers.
- Never sum alternative commission representations or item and conversion totals together.
- Never label `clickTime` as total clicks or calculate a conversion rate.
